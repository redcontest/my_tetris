# Gravity Tetris

Мой вариант знаменитой игры **Tetris** на Python для защиты на экзамене (а
может даже и дальнейшего развития).

В этом проекте я старался писать адекватный чистый код, продумывал архитектуру,
старался довести ее до идеала, насколько позволяла первоначальная задумка,
конечно. Хотя я и не игродел, могу сказать, что это было прикольно.

## Возможности моего блестящего шедевра:

- самое обычное падение тетромино;
- песочный режим гравитации, в котором зафиксированные блоки осыпаются вниз;
- режим `wrap`, позволяющий тетромино частично выходить за левую или правую
  границу поля и появляться с другой стороны;
- SRS wall kicks для поворота фигур у стен (самое "сложное", что взял из
  классического тетриса);
- ghost piece, показывающий место падения текущей фигуры;
- счет, уровни, ускорение падения с ростом уровня;
- главное меню, настройки, пауза и экран завершения игры;
- управление с поддержкой физических клавиш `WASD` независимо от раскладки.
- ну и кавайная розовая палитра, конечно, куда без этого?

## Управление

| Действие | Клавиши |
| --- | --- |
| Движение влево | `Left`, `A` |
| Движение вправо | `Right`, `D` |
| Поворот | `Up`, `W` |
| Soft drop | `Down`, `S` |
| Hard drop | `Space` |
| Пауза | `Esc`, `P` |
| Выход из паузы | `Esc` или кнопка `ПРОДОЛЖИТЬ` |

Soft drop - усоренное падение, Hard drop - мгновенное. В обычном тетрисе
называется прям слово в слово. Почему на P пауза? Возможно, кому-то будет
удобнее тянуться до P, если играть стрелками.

## Режимы игры

| Режим | Описание |
| --- | --- |
| `STANDARD` | Обычный тетрис: фигуры падают и фиксируются на доске. |
| `SAND` | Зафиксированные клетки постепенно осыпаются вниз как песок. |
| `WRAP OFF` | Фигура не может выходить за боковые границы поля. |
| `WRAP ON` | Фигура может частично уходить за боковую границу и появляться с другой стороны. |

Режимы выбираются в меню настроек ДО начала игры, менять в процессе НЕЛЬЗЯ
(а то было бы слишком просто!)

## Алгоритмы

| Алгоритм | Где используется | Суть | Сложность реализации |
| --- | --- | --- | --- |
| Проверка размещения тетромино | `Board`, `MoveController` | Каждая занятая клетка фигуры проверяется на выход за границы и столкновение с уже занятыми клетками. | Легко |
| Очистка заполненных линий | `Board` | Полные строки удаляются, сверху добавляется такое же количество пустых строк. | Легко |
| Стандартное падение | `EventController`, `MoveController` | По таймеру фигура пытается сместиться вниз на одну клетку, а при столкновении фиксируется на доске. | Легко |
| Soft drop | `EventController`, `MoveController`, `Score` | При удержании клавиши падение использует меньшую задержку, а игрок получает очки за быстрый спуск. | Легко |
| Hard drop | `MoveController`, `Score` | Фигура двигается вниз до первого столкновения, фиксируется и начисляет очки за пройденные клетки. | Средне |
| SRS wall kicks | `MoveController` | При повороте проверяется набор стандартных смещений, чтобы фигура могла повернуться рядом со стеной или блоками. | Средне |
| Ghost piece | `MoveController` | Копия текущей фигуры опускается вниз до последней возможной позиции и передается в состояние для отрисовки. | Средне |
| Песочная гравитация | `Board`, `EventController` | Зафиксированные клетки по одной осыпаются вниз, если клетка под ними свободна и не занята текущей фигурой. | Средне |
| Wrap-режим | `MoveController`, `TetrominoRenderer` | Координата X заворачивается через `% width`, поэтому часть фигуры может уходить за край и появляться с другой стороны. | Средне |
| Мешок тетромино | `TetrominoBag` | Все типы фигур перемешиваются и выдаются по одному, после опустошения мешок заполняется заново. | Легко |
| Рост уровня и скорости | `Score`, `EventController` | Уровень зависит от количества очищенных линий, а задержка падения уменьшается с ростом уровня. | Легко |
| Конечный автомат состояний | `GameState`, `EventController`, `MainRenderer` | Игра переключается между меню, настройками, игровым процессом, паузой и экраном завершения. | Легко |

## Архитектура

Проект построен по большей части по архитектуре **MVC**:

- **Model** - игровые сущности из `models/`: доска, счет, тетромино и мешок
  фигур (улучшенный рандомайзер);
- **Controller** - классы из `controllers/`, которые обрабатывают ввод,
  обновляют игровую сессию и меняют состояние игры;
- **View** - классы из `views/`, которые только отрисовывают текущее состояние.

Связь между частями устроена через `GameState`: контроллеры обновляют модели и
синхронизируют их состояние при каждом изменении, а рендереры берут данные из
состояния и отрисовывают кадр. Очень наглядно, помогает не путать все на свете.

### Оркестрация игры

Главный объект приложения - `Game`. Он создает окно Pygame, хранит общий
`GameState`, подключает `EventController` и `MainRenderer`, а затем запускает
главный цикл игры.

Внутри каждого кадра происходит один и тот же сценарий:

1. `Game` получает события Pygame и передает их в `EventController`.
2. `EventController` обрабатывает ввод и вызывает нужные действия игровой
   логики.
3. `GameSession` хранит текущие модели партии: доску, счет, текущую фигуру,
   ghost piece, режим гравитации и режим `wrap`.
4. `MoveController` отвечает за движение, поворот, падение, фиксацию фигур и
   вычисление ghost piece.
5. `GameSession` синхронизирует актуальные модели в `GameState`.
6. `MainRenderer` смотрит на текущее состояние и выбирает, какой экран нужно
   отрисовать.

`MainRenderer` сам не рисует вообще ничего (название говорящее прям), он
только оркестрирует рендеринг и делегирует работу подчиненным рендерам:

- `BoardRenderer` рисует игровую доску и зафиксированные клетки;
- `TetrominoRenderer` рисует текущую фигуру и ghost piece;
- `UiRenderer` рисует меню, настройки, паузу, game over и игровую информацию;
- `UiDetails` содержит базовые операции отрисовки текста и кнопок, они

Разбито все на подрендеры и подконтроллеры по одной простой причине: кода стало
слишком много, пришлось разбивать на классы (старался без костылей все
разбить, но я в этом деле не лучший).

| Папка / файл | Назначение |
| --- | --- |
| `main.py` | Точка входа: создает `Game` и запускает игру. |

| `src/tetris/config.py` | Общие настройки проекта: окно, цвета, UI, баланс скорости и счета. |
| `src/tetris/models/` | Игровые сущности: доска, счет, тетромино, мешок фигур. |
| `src/tetris/controllers/` | Обработка событий, движение фигур, состояние игровой сессии. |
| `src/tetris/views/` | Отрисовка доски, тетромино, UI и экранов игры. |
| `tests/` | Pytest-тесты для моделей, контроллеров и smoke-тесты рендера. |

## Установка

Нужен Python 3.13 или совместимая версия Python 3.

Создать и активировать виртуальное окружение:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

Установить зависимости:

```powershell
python -m pip install -r requirements.txt
```

## Запуск игры

Из папки проекта:

```powershell
python main.py
```

Если запуск выполняется из родительской папки:

```powershell
python .\my_tetris\main.py
```

## Тесты

Запуск всех тестов:

```powershell
python -m pytest tests
```

conftest.py тут нужен, чтобы заставить пайтест корректно тестировать все, не
открывая окно пайгейма. Флаг `SDL_VIDEODRIVER=dummy` как раз отвечает за это.

Текущий набор тестов проверяет:

- работу доски и очистку линий;
- песочную гравитацию;
- счет, уровни и очки за падение;
- мешок тетромино;
- движение, hard drop, soft drop, SRS wall kicks и wrap;
- синхронизацию `GameSession` и `GameState`;
- обработку событий меню, настроек, паузы и игры;
- базовую работоспособность рендера без реального окна.
